PART 01 Project-Based Questions
Q1 What is TheSchoolTech? 🔥 Must Know
Interview Answer
TheSchoolTech is a full-stack web platform built with Laravel that connects private schools with verified computer trainers. School principals can browse trainer profiles, book them for 1, 2, or 3 months, and pay securely online via Razorpay. Trainers can register, showcase their skills with demo videos, and manage their bookings.
TheSchoolTech Example
The platform has 3 user roles — Admin, School Principal, and Trainer — each with their own dashboard and access controls implemented via custom RoleMiddleware.
Q2 What problem does TheSchoolTech solve? 🔥
Many private schools in India, especially in UP and Bihar, don't have dedicated computer teachers. Students miss out on modern skills like AI, Python, and MS Office. TheSchoolTech solves this by providing a marketplace where schools can hire qualified trainers on short-term contracts without the burden of a permanent salary.
Q3 What are the main modules of the system? 🔥
1. Authentication Module — Register, Login, Role-based access
2. Trainer Module — Profile, photo/video upload, subject selection
3. School Module — Search, filter trainers, manage profile
4. Booking Module — Create, track, cancel bookings
5. Payment Module — Razorpay integration, order creation, verification
6. Admin Module — Approve trainers, monitor bookings, manage subjects
7. Review Module — Rating and feedback after completed training
8. Email Module — Notifications via Laravel Mailable
Q4 What technologies did you use and why? 🔥
Laravel 13 — Rapid development, built-in auth, Eloquent ORM, Blade templating
PHP 8.3 — Server-side language, latest features like named arguments, enums
MySQL — Relational database, perfect for structured school/trainer/booking data
Bootstrap 5 — Responsive UI quickly without writing CSS from scratch
Razorpay — Indian payment gateway, supports UPI, cards, net banking
Hostinger — Deployment platform for PHP applications
Q5 Explain the complete database structure.
users — id, name, email, password, role (admin/school/trainer), phone, city, is_active
trainer_profiles — user_id (FK), bio, qualification, experience_years, rate_1month/2month/3month, photo, demo_video, youtube_link, teaching_subjects (JSON), skills (JSON), approval_status
school_profiles — user_id (FK), school_name, principal_name, address, board, student_count
subjects — name, category, icon, color
bookings — school_id (FK), trainer_id (FK), duration_months, start_date, end_date, status, total_amount, subjects (JSON), payment_status, payment_id
reviews — booking_id (FK), school_id, trainer_id, rating, comment
Q6 How does the booking flow work end to end? 🔥
1. School searches trainers, filters by subject/city/rate
2. School clicks "Book Now" on trainer profile
3. School fills booking form — duration (1/2/3 months), start date, subjects
4. Booking saved with status = pending
5. Trainer receives email notification
6. Trainer accepts → status = accepted
7. School sees "Pay Now" button, completes Razorpay payment
8. Razorpay signature verified server-side → status = active
9. Training happens (1-3 months)
10. Laravel Scheduler auto-sets status = completed after end_date
11. School can leave review/rating
Q7 How does trainer approval work?
When a trainer registers, their profile is saved with approval_status = 'pending'. Admin sees pending trainers in their dashboard. Admin can Approve or Reject. Only approved trainers appear in the public trainer listing. When approved, trainer receives an email notification via TrainerApprovedMail.
Q8 How is role-based access implemented? 🔥
A custom RoleMiddleware checks Auth::user()->role against allowed roles. Routes are grouped with this middleware:
Route::middleware(['auth', 'role:school'])->prefix('school')...
The middleware is registered in bootstrap/app.php using $middleware->alias(['role' => RoleMiddleware::class]). If the user's role doesn't match, a 403 is returned.
Q9 How did you handle file uploads (photo and video)?
Files are uploaded via multipart form. In the controller, $request->hasFile('photo') checks if a file exists, then $file->store('trainers/photos', 'public') saves it. Old files are deleted using Storage::disk('public')->delete($oldPath). For videos, both direct MP4 upload and YouTube URL embed are supported. YouTube links are parsed with regex to extract the embed ID.
Q10 What is the most difficult feature you built?
The Razorpay payment integration was most challenging. Specifically, server-side signature verification — ensuring payment isn't faked by the client. I used $this->api->utility->verifyPaymentSignature() which uses HMAC-SHA256 to verify that the payment_id + order_id signature matches what Razorpay actually sent, preventing fraudulent requests.
Q11 How does the rating system work?
After a booking is marked completed, the school can submit a rating (1-5) and comment. This is stored in the reviews table. The trainer's average rating is calculated using a computed attribute: $this->reviews()->avg('rating'). This average is shown on trainer cards and profile pages.
Q12 How do email notifications work?
Using Laravel Mailable classes. When a booking is created, Mail::to($trainer->email)->send(new BookingReceivedMail($booking)) is called. Each Mailable has an envelope (subject) and content (blade view). SMTP is configured in .env using Hostinger's smtp.hostinger.com on port 465 with SSL. Notifications trigger for: booking received, accepted, rejected, completed, and trainer approved.
Q13 How does the auto-completion of bookings work?
A custom Artisan command bookings:complete queries all active bookings where end_date < today and updates their status to completed. This command is scheduled in routes/console.php to run daily at midnight using Schedule::command('bookings:complete')->dailyAt('00:00'). On Hostinger, a cron job runs php artisan schedule:run every minute.

Q16 Why did you store teaching_subjects as JSON in the database?
Teaching subjects is a flexible, variable-length list per trainer. Creating a separate pivot table (trainer_subjects) would be more normalized but overkill for this use case. JSON storage is simpler to implement and fast enough for filtering. Laravel's $casts = ['teaching_subjects' => 'array'] automatically handles JSON encode/decode. The tradeoff is that JSON columns can't be indexed efficiently for complex queries.
Q17 How do you prevent a school from booking the same trainer twice?
In BookingController@create, we query for existing active bookings: Booking::where('school_id', $school->id)->where('trainer_id', $trainer->id)->whereIn('status', ['pending','accepted','active'])->first(). If found, the booking page shows a warning alert instead of the form.
Q18 How is password security handled?
Passwords are hashed using Hash::make($password) which uses bcrypt algorithm. During login, Auth::attempt(['email' => $email, 'password' => $password]) uses Hash::check() internally. Plain-text passwords are never stored. For password change, Hash::check($currentPassword, $user->password) verifies the old password before updating.
Q19 How does trainer filtering/search work?
In TrainerController@index, a query builder starts with all approved/available trainers. Filters are applied conditionally using $request->filled() to check if parameter is present. For subject filtering, whereJsonContains('teaching_subjects', $subject) is used. City uses LIKE search. Results are paginated with paginate(12)->withQueryString() to preserve filter parameters in pagination links.
Q20 What is the difference between TrainerProfile and User models?
User stores authentication data — email, password, role, basic contact info. TrainerProfile stores professional data — bio, qualifications, rates, subjects, approval status. They have a one-to-one relationship: User hasOne TrainerProfile. This separation follows Single Responsibility Principle and makes it easy to add different profile types (school, trainer) without modifying the core User model.

Hard Explain the most challenging feature.

PART 03 PHP Interview Questions
Q1 What is the difference between include and require? 🔥
Both include a PHP file. require causes a fatal error (E_COMPILE_ERROR) if the file is not found and stops execution. include only shows a warning and continues. Use require when the file is essential (like config), include when optional.
Q2 What are PHP superglobals? ⭐
Superglobals are built-in variables accessible from anywhere without using global. Main ones: $_GET, $_POST, $_SESSION, $_COOKIE, $_SERVER, $_FILES, $_ENV, $_REQUEST, $GLOBALS.
In TheSchoolTech
Laravel abstracts these — we use $request->input(), $request->file(), session() instead of raw superglobals for security and convenience.
Q3 What is the difference between GET and POST? 🔥
GET — Data sent in URL, visible, cached, bookmarkable, max ~2048 chars. Used for reading/searching data.
POST — Data in request body, not visible in URL, not cached, no size limit. Used for creating/modifying data. In TheSchoolTech, booking forms use POST. Trainer search uses GET (so filters can be bookmarked/shared).
Q4 How does session work in PHP?
Session stores data server-side. PHP creates a unique session ID stored as a cookie in the browser. On each request, PHP reads the session ID from cookie, loads the corresponding server-side file. session_start() initializes it. Data stored in $_SESSION. In Laravel, configured via SESSION_DRIVER in .env (file, database, redis).
Q5 What is a closure in PHP? ⭐
A closure is an anonymous function that can capture variables from its outer scope using use.
$multiplier = 3; $multiply = function($n) use ($multiplier) { return $n * $multiplier; }; echo $multiply(5); // 15
In TheSchoolTech, closures are used in route definitions, query scopes, and collection operations like ->filter(function($item) {...}).
Q6 What is PDO and why use it? ⭐
PDO (PHP Data Objects) is a database abstraction layer that supports multiple databases (MySQL, PostgreSQL, SQLite). Key benefit: prepared statements that prevent SQL injection. Laravel's Eloquent and Query Builder use PDO internally. We never write raw PDO in TheSchoolTech — Laravel handles it.
Q7 What is SQL injection and how to prevent it?
SQL injection is when malicious SQL is injected via user input: SELECT * FROM users WHERE email = '' OR 1=1 --'. Prevention: use prepared statements / parameterized queries. In Laravel, Eloquent and Query Builder use PDO prepared statements automatically. Never use raw string concatenation with user input.
Q8 What is Composer?
Composer is PHP's dependency manager. It manages packages listed in composer.json. composer install installs dependencies, composer require package adds new ones. TheSchoolTech uses it for Laravel framework, Razorpay SDK (razorpay/razorpay), and other packages.
Q9 What is autoloading in PHP?
Autoloading automatically loads PHP classes without manual require statements. PSR-4 is the standard. Composer generates vendor/autoload.php. In Laravel, all classes in app/ are autoloaded via "App\\": "app/" in composer.json.
Q10 What are namespaces in PHP?
Namespaces organize code and prevent naming conflicts. Like folders for class names. In TheSchoolTech: namespace App\Http\Controllers; — the TrainerController lives in this namespace. We can have two classes named "Controller" in different namespaces without conflict.
Q11 What is the difference between == and ===?
== compares values with type coercion (0 == "0" is true). === compares values AND type strictly (0 === "0" is false). Always use === in security-sensitive code to avoid bugs.
Q12 What is exception handling in PHP? ⭐
try { $this->api->utility->verifyPaymentSignature([...]); // success } catch (\Exception $e) { // handle failure - in TheSchoolTech, redirect with error return redirect()->back()->with('error', 'Payment failed'); }
In TheSchoolTech, Razorpay signature verification is wrapped in try-catch so if verification fails, the booking doesn't get activated and the user sees an error message.
PART 04 PHP OOP Interview Questions
Q1 What are the 4 pillars of OOP? 🔥
Encapsulation — Hiding internal data, exposing only what's needed via public methods. TrainerProfile model encapsulates database logic.
Inheritance — Child class inherits parent. In Laravel, class TrainerController extends Controller. All Mailable classes extend Mailable.
Polymorphism — Same method name, different behavior. The handle() method in all Mailable classes behaves differently.
Abstraction — Hiding complex implementation. We call $booking->update(['status' => 'active']) without knowing the SQL underneath.
Q2 What is the difference between abstract class and interface? 🔥
Abstract class — Can have implemented methods + abstract methods. Single inheritance only. Used as base class.
Interface — Only method signatures (no implementation). A class can implement multiple interfaces.
In Laravel: Mailable is abstract-like. Contracts (like ShouldQueue) are interfaces. Our BookingReceivedMail extends Mailable.
Q3 What is a Trait in PHP? ⭐
Traits are code reuse mechanisms for single-inheritance languages. A class can use multiple traits. In TheSchoolTech: class Booking extends Model { use HasFactory, Notifiable; }. HasFactory adds factory methods, Notifiable adds notification capabilities. Traits let us add these features without complex inheritance.
Q4 What are access modifiers? 🔥
public — Accessible from anywhere. Most model methods are public.
protected — Accessible within class and child classes. $fillable in Eloquent models is protected.
private — Only within the class. In PaymentController, private Api $api.
class PaymentController extends Controller { private Api $api; // private public function __construct() { // public $this->api = new Api(config('razorpay.key'), config('razorpay.secret')); } }
Q5 What is Dependency Injection? 🔥
Dependency Injection means providing dependencies to a class from outside rather than the class creating them itself. Laravel's service container handles DI automatically.
// Laravel injects Request automatically public function store(Request $request, TrainerProfile $trainer) { // $request and $trainer injected by Laravel }
In TheSchoolTech, route model binding automatically injects Trainer, Booking models based on route parameters.
Q6 What is static in PHP?
Static methods/properties belong to the class, not an instance. Called without creating an object: User::find(1), Booking::where(...). In Eloquent, all query methods are static-accessible via magic methods. The static keyword in late static binding refers to the called class.
Q7 What is method overriding?
Child class defines a method with the same name as parent, replacing the parent's behavior. In Laravel, the handle() method in each Mailable overrides the parent's abstract method. The rules() method in Form Requests overrides the base class.
Q8 What is the constructor and destructor?
__construct() runs when object is created. Used for initialization. In PaymentController, the constructor initializes the Razorpay API object. __destruct() runs when object is destroyed (out of scope). Rarely used in web applications.
PART 05 Laravel Interview Questions
Q1 What is Laravel MVC architecture? 🔥
Model — Eloquent classes (User, Booking, TrainerProfile) — handle data and database logic.
View — Blade templates (home.blade.php, school/dashboard.blade.php) — handle presentation.
Controller — (TrainerController, BookingController) — handle request/response, call models, return views.
Flow: Request → Route → Middleware → Controller → Model → Controller → View → Response.
Q2 What is Middleware in Laravel? 🔥
Middleware runs before/after HTTP requests. Like a filter pipeline. In TheSchoolTech: auth middleware checks if user is logged in. Custom RoleMiddleware checks if user has correct role. CSRF middleware validates form tokens. If middleware fails, request is rejected before reaching controller.
Route::middleware(['auth', 'role:school'])->group(function () { Route::get('/dashboard', [SchoolController::class, 'dashboard']); });
Q3 What is Eloquent ORM? 🔥
Eloquent is Laravel's ORM (Object Relational Mapper). Each database table has a corresponding Model class. Instead of writing SQL, you write PHP: Booking::where('status', 'active')->get(). Eloquent handles relationships, casting, mass assignment protection, timestamps automatically. In TheSchoolTech, all database operations use Eloquent.
Q4 What is $fillable and why is it important? 🔥
$fillable is a whitelist of columns that can be mass-assigned via Model::create() or $model->fill(). Without it, a malicious user could submit extra form fields like role=admin and override protected columns. It prevents Mass Assignment vulnerability.
// In User model - role is in fillable but // controlled — only set explicitly in controller protected $fillable = ['name', 'email', 'password', 'role', ...];
Q5 What are Eloquent relationships? Explain with TheSchoolTech. 🔥
hasOne: User hasOne TrainerProfile (one user → one trainer profile)
belongsTo: TrainerProfile belongsTo User (trainer profile → its user)
hasMany: TrainerProfile hasMany Bookings (one trainer → many bookings)
hasMany: TrainerProfile hasMany Reviews
// Usage in controller $trainer = TrainerProfile::with('user', 'reviews')->find($id); echo $trainer->user->name; // User's name echo $trainer->reviews->count(); // Number of reviews
Q6 What is N+1 problem and how to solve it? 🔥
N+1 problem: if you load 10 trainers and then loop to get each trainer's user, Laravel makes 1 (get trainers) + 10 (get each user) = 11 queries. Fix: eager loading with with().
// ❌ N+1 problem $trainers = TrainerProfile::all(); foreach ($trainers as $t) { echo $t->user->name; } // 1+N queries // ✅ Eager loading - only 2 queries $trainers = TrainerProfile::with('user')->get();
In TheSchoolTech, all trainer listings use with('user') to avoid N+1.
Q7 What are Migrations?
Migrations are version control for the database schema. They're PHP files that define table structure. php artisan migrate runs them in order. php artisan migrate:rollback reverses them. In TheSchoolTech, separate migrations for users, trainer_profiles, school_profiles, subjects, bookings, reviews tables. Also an alter migration to add demo_video column was added separately.
Q8 What are Seeders?
Seeders populate the database with test/default data. php artisan db:seed runs the DatabaseSeeder. In TheSchoolTech, the seeder creates: 18 subjects with icons/colors, admin user, demo school, and 3 demo trainers with pre-approved status. firstOrCreate() prevents duplicates on re-seeding.
Q9 What is CSRF and how does Laravel handle it? 🔥
CSRF (Cross-Site Request Forgery) is when a malicious site tricks a user's browser into making requests to your site. Laravel generates a unique CSRF token per session. Every HTML form must include @csrf which adds a hidden _token field. The VerifyCsrfToken middleware validates this token on every POST/PUT/DELETE request. Ajax requests need the token in headers.
Q10 What are Accessors and Mutators? ⭐
Accessor — formats attribute when getting. Mutator — transforms attribute when setting.
// Accessor in TrainerProfile public function getAverageRatingAttribute(): float { return round($this->reviews()->avg('rating') ?? 0, 1); } // Usage: $trainer->average_rating (auto-called) // Accessor for YouTube embed ID public function getYoutubeEmbedIdAttribute(): ?string { preg_match('/(?:youtube\.com\/watch\?v=|youtu\.be\/)([^&]+)/', $this->youtube_link, $matches); return $matches[1] ?? null; }
Q11 What are Laravel Collections?
Collections are a fluent wrapper around arrays with powerful methods. Eloquent returns collections. In TheSchoolTech: $bookings->where('status', 'pending') in the Blade template filters a collection. Methods: filter(), map(), pluck(), groupBy(), count(), sum() etc.
Q12 What is Laravel Mailable? ⭐
Mailable is a class that represents an email. Each email type in TheSchoolTech has its own Mailable: BookingReceivedMail, BookingAcceptedMail, BookingRejectedMail, BookingCompletedMail, TrainerApprovedMail. They define the subject (Envelope), template (Content), and attachments. Sent via Mail::to($email)->send(new BookingAcceptedMail($booking)).
Q13 What is the Service Container in Laravel?
The Service Container is Laravel's IoC (Inversion of Control) container — it manages class dependencies and performs dependency injection. When you type-hint a class in a controller constructor or method, Laravel automatically resolves and injects it. Route model binding is an example — TrainerProfile $trainer in a method is automatically fetched from DB.
Q14 What is Route Model Binding?
Laravel automatically fetches model instances from route parameters. If route is /booking/{booking} and controller has Booking $booking, Laravel fetches the Booking by ID automatically. If not found, returns 404. In TheSchoolTech used in BookingController, PaymentController for booking operations.
Q15 What is Laravel Scheduler?
Laravel Scheduler defines recurring tasks. In routes/console.php: Schedule::command('bookings:complete')->dailyAt('00:00'). A single cron entry on the server runs php artisan schedule:run every minute, and Laravel determines which scheduled tasks are due. In TheSchoolTech, used to auto-complete bookings daily.
Q16 What is Blade templating?
Blade is Laravel's templating engine. Features: @extends, @section, @yield for layouts. @foreach, @if, @forelse for logic. {{ $var }} for escaped output, {!! $var !!} for unescaped (like status_badge HTML). @csrf for CSRF tokens. Compiled to plain PHP and cached. TheSchoolTech has layouts/app.blade.php, layouts/dashboard.blade.php as master layouts.
Q17 What is Pagination in Laravel?
paginate(12) on a query returns a Paginator instance. withQueryString() preserves URL parameters (filters) in page links. In views: {{ $trainers->links() }} renders Bootstrap-compatible page numbers. In TheSchoolTech, trainer listing, bookings, admin tables all use pagination.
Q18 What is the difference between get() and first() in Eloquent?
get() returns a Collection (array of models). first() returns a single Model or null. find($id) returns model by primary key or null. findOrFail($id) returns model or throws 404. In TheSchoolTech, first() used to check existing bookings, get() used for listings.
PART 06 MySQL / SQL Interview Questions
Q1 What is the difference between INNER JOIN, LEFT JOIN, RIGHT JOIN? 🔥
INNER JOIN — Returns rows where match exists in BOTH tables.
LEFT JOIN — Returns all rows from left table + matching from right (NULL if no match).
RIGHT JOIN — Returns all rows from right table + matching from left.
-- Get all bookings with trainer name (INNER - only matched) SELECT b.*, u.name FROM bookings b INNER JOIN trainer_profiles tp ON b.trainer_id = tp.id INNER JOIN users u ON tp.user_id = u.id; -- Get all trainers even if no bookings (LEFT) SELECT tp.*, COUNT(b.id) as bookings FROM trainer_profiles tp LEFT JOIN bookings b ON tp.id = b.trainer_id GROUP BY tp.id;
Q2 What is the difference between WHERE and HAVING?
WHERE filters rows before aggregation. HAVING filters after GROUP BY aggregation.
-- Trainers with more than 2 bookings SELECT trainer_id, COUNT(*) as total FROM bookings WHERE status = 'completed' -- filter before grouping GROUP BY trainer_id HAVING COUNT(*) > 2; -- filter after grouping
Q3 What is Normalization? Explain 1NF, 2NF, 3NF. 🔥
1NF — No repeating groups, atomic values, each column has single value.
2NF — 1NF + no partial dependencies (non-key columns depend on WHOLE primary key).
3NF — 2NF + no transitive dependencies (non-key columns don't depend on other non-key columns).

TheSchoolTech DB is mostly 3NF. Note: teaching_subjects stored as JSON technically violates 1NF — a design tradeoff for flexibility.
Q4 What is ACID in database transactions? ⭐
Atomicity — Transaction is all-or-nothing.
Consistency — DB moves from one valid state to another.
Isolation — Concurrent transactions don't interfere.
Durability — Committed data persists even after crash.

In TheSchoolTech, payment processing should ideally use DB transactions:
DB::transaction(function() use ($booking, $request) { $booking->update(['payment_status' => 'paid', 'status' => 'active']); // If this fails, payment_status update also rolls back });
Q5 What is the difference between DELETE, TRUNCATE, DROP?
DELETE — Removes specific rows, logged, can WHERE, can rollback.
TRUNCATE — Removes all rows, not logged per row, faster, resets auto-increment, can't rollback easily.
DROP — Removes entire table structure and data permanently.
Q6 What is an Index and why use it? ⭐
Index speeds up SELECT queries by creating a data structure (B-tree) for fast lookups. Without index, MySQL scans every row. In TheSchoolTech: email in users table has UNIQUE index (fast login lookups). approval_status in trainer_profiles should be indexed (frequently filtered). Foreign keys automatically create indexes. Tradeoff: faster reads but slower writes and more storage.
Q7 Explain the bookings table design and why.
Bookings table connects schools and trainers with: school_id FK (→ school_profiles), trainer_id FK (→ trainer_profiles). Status enum: pending/accepted/rejected/active/completed/cancelled — tracks the full lifecycle. payment_id stores Razorpay payment ID for reconciliation. subjects JSON stores selected subjects per booking (flexible, varies per booking). total_amount stored at booking time so rate changes don't affect existing bookings.
Q8 What is a foreign key constraint?
A foreign key ensures referential integrity — a row in child table can't reference a non-existent row in parent table. In TheSchoolTech: bookings.school_id references school_profiles.id. cascadeOnDelete() means if a school profile is deleted, all their bookings are also deleted automatically. Without FK constraints, orphan data can accumulate.
Q9 What is UNION vs UNION ALL?
UNION combines results of two queries and removes duplicates (slower). UNION ALL combines and keeps all rows including duplicates (faster). Use UNION ALL when you know results won't have duplicates or when duplicates are acceptable.
Q10 How to get average rating per trainer from the reviews table?
SELECT tp.id, u.name, AVG(r.rating) as avg_rating, COUNT(r.id) as total_reviews FROM trainer_profiles tp JOIN users u ON tp.user_id = u.id LEFT JOIN reviews r ON tp.id = r.trainer_id GROUP BY tp.id, u.name ORDER BY avg_rating DESC;
In Eloquent: $this->reviews()->avg('rating') does this query automatically.
PART 07 Razorpay / Payment Interview Questions
Q1 Explain the complete Razorpay payment flow in TheSchoolTech. 🔥
Step 1 — Order Creation (Server): When school clicks Pay, PaymentController@showPayment calls Razorpay API to create an order with amount (in paise), currency INR, and booking reference. Returns an order_id.

Step 2 — Checkout (Client): The order_id is passed to the Razorpay checkout.js on the payment page. User pays via card/UPI/netbanking in Razorpay's popup.

Step 3 — Response (Client): Razorpay sends back razorpay_payment_id, razorpay_order_id, razorpay_signature to the browser.

Step 4 — Verification (Server): These are submitted via hidden form to verifyPayment(). Server verifies signature = HMAC-SHA256(order_id + "|" + payment_id, secret_key).

Step 5 — Activation: If valid, booking status → active, payment_status → paid. Redirect with success message.
Q2 Why do we verify the signature server-side? 🔥
Without server-side verification, anyone could fake a payment response. They could manually call the verify endpoint with made-up payment_id and order_id values. The signature is generated using the Razorpay Secret Key (which only we and Razorpay know). Only a genuine Razorpay payment will produce the correct signature. This prevents fraudulent booking activations without actual payment.
Q3 What if payment succeeds on Razorpay but our server fails to update? 🔥
This is a critical edge case. Solutions: 1) Use Razorpay Webhooks — Razorpay sends a POST to our webhook endpoint when payment succeeds. Even if user closed browser, webhook updates the DB. 2) The payment_id stored in booking allows manual reconciliation. 3) Use DB transactions so payment_status and status update atomically. In TheSchoolTech currently webhooks are not implemented — an improvement to add.
Q4 What is the difference between order_id and payment_id?
order_id (e.g., order_xxx) — Created by our server BEFORE payment. Represents the intent to pay. Stored in booking record.
payment_id (e.g., pay_xxx) — Generated by Razorpay AFTER successful payment. Represents the actual completed transaction. Stored after verification.
Q5 How to prevent duplicate payments?
In showPayment(), we check if ($booking->payment_status === 'paid') return back()->with('error', 'Already paid'). Also, Razorpay orders are idempotent — the same order_id can't be paid twice. The signature verification also ensures each payment is unique and from Razorpay. A receipt field in the order can be checked for uniqueness.
Q6 Why is the amount in paise, not rupees?
Razorpay API requires amount in the smallest currency unit to avoid floating point issues. For INR, 1 rupee = 100 paise. So ₹15,000 = 1,500,000 paise. In code: 'amount' => $booking->total_amount * 100. This prevents rounding errors that could occur with decimal rupee amounts.
Q7 What are Razorpay test credentials?
Test mode uses keys starting with rzp_test_. Test cards: 4111 1111 1111 1111 (Visa), expiry 12/25, CVV 123, OTP 1234. No real money is charged. For production, keys start with rzp_live_ and real payments are processed. Always use environment variables — never hardcode keys in source code.
Q8 Why did you choose Razorpay over other payment gateways?
Razorpay is India-focused: supports UPI, IMPS, NEFT which Indian schools prefer. Easy PHP SDK. Simple integration. Good documentation. No monthly fee — only per-transaction (2%). Supports test mode for development. Alternative: PayU, Cashfree — but Razorpay has better developer experience and wider adoption in India.
PART 08 REST API Interview Questions
Q1 What is a REST API? 🔥
REST (Representational State Transfer) is an architectural style for APIs using HTTP. Key principles: Stateless, Client-Server, Uniform interface (standard HTTP methods), Resource-based URLs. Each request contains all necessary info — server doesn't store client state between requests.
Q2 What are HTTP methods and when to use each? 🔥
GET — Read data. GET /trainers (list), GET /trainers/1 (single)
POST — Create new resource. POST /bookings
PUT — Update entire resource. PUT /school/profile
PATCH — Partial update. PATCH /booking/1 (just status)
DELETE — Delete resource. DELETE /video/1
Q3 What are HTTP status codes? 🔥
200 OK — Success
201 Created — Resource created
301/302 — Redirect (used after form submissions in TheSchoolTech)
400 Bad Request — Invalid input
401 Unauthorized — Not logged in
403 Forbidden — Logged in but no permission (role mismatch)
404 Not Found — Resource doesn't exist
422 Unprocessable — Validation failed
500 Internal Server Error — Server crash
Q4 What is the Razorpay API call in TheSchoolTech?
// POST to Razorpay API $order = $this->api->order->create([ 'receipt' => 'booking_' . $booking->id, 'amount' => $booking->total_amount * 100, 'currency' => 'INR', 'payment_capture' => 1, ]); // Returns: { id: "order_xxx", amount: 1500000, currency: "INR", ... }
This is an HTTP POST to Razorpay's API. The SDK handles authentication using Basic Auth with the API key and secret.
Q5 REST vs SOAP — what's the difference?
REST — Lightweight, uses JSON/XML, stateless, uses standard HTTP, easy to use, modern standard.
SOAP — Heavyweight, XML only, has its own protocol, strict standards (WSDL), used in enterprise/banking.
Razorpay uses REST API. Laravel also makes REST APIs easy with API routes and resources.
PART 09 Authentication & Security Questions
Q1 Authentication vs Authorization — difference? 🔥
Authentication — WHO are you? Verified via email+password login. Laravel's Auth::attempt().
Authorization — WHAT can you do? Checked via RoleMiddleware. A trainer CAN'T access school dashboard even if logged in.
In TheSchoolTech: First auth middleware checks if logged in (authentication). Then role:school middleware checks if role is school (authorization).
Q2 How does login work in TheSchoolTech? 🔥
Auth::attempt(['email' => $email, 'password' => $password]) — Laravel finds user by email, then uses Hash::check() to compare password with stored bcrypt hash. If match, creates session, sets Auth::user(). After login, redirected based on role using match($user->role) { 'admin' => route('admin.dashboard'), ... }.
Q3 What is XSS and how does Laravel prevent it? ⭐
XSS (Cross-Site Scripting) — attacker injects malicious JavaScript into the page that runs in other users' browsers. Laravel's Blade {{ $var }} automatically HTML-encodes output, converting <script> to &lt;script&gt;. Only use {!! $var !!} for trusted content (like the status_badge in TheSchoolTech which generates our own HTML).
Q4 How is file upload secured in TheSchoolTech?
1. mimes:jpg,jpeg,png validation — only image types allowed for photo
2. mimes:mp4,mov,avi,webm — only video types for demo video
3. max:2048 (2MB) for photos, max:51200 (50MB) for videos
4. Files stored in storage/app/public — outside web root
5. Laravel generates random filename — prevents path traversal attacks
6. storage:link creates symlink so files are web-accessible without exposing storage directory
Q5 How do you prevent Mass Assignment vulnerability? ⭐
Using $fillable in all models. Example: if someone sends POST /register with role=admin, Laravel won't set it via User::create($request->all()) if role is not handled. Better practice: use $request->only(['name', 'email', 'password']) instead of $request->all(). The role is set explicitly: 'role' => 'school'.
Q6 How do you secure .env file and API keys?
1. Never commit .env to Git — add to .gitignore
2. Store in environment variables on server
3. Razorpay keys in .env: RAZORPAY_KEY, RAZORPAY_SECRET
4. Access via config('razorpay.key') — never hardcode
5. On production: APP_DEBUG=false — never expose errors
6. Hostinger: use File Manager or SSH to set .env — not visible in browser
PART 10 HTML / CSS / JavaScript Questions
Q1 What is the CSS Box Model? ⭐
Every HTML element is a box: Content → Padding → Border → Margin. box-sizing: border-box (set in TheSchoolTech's CSS) includes padding and border in the element's total width — predictable layout. Without it, adding padding increases element's total size.
Q2 What is Flexbox? How is it used in TheSchoolTech?
Flexbox is a CSS layout model for 1D layouts (row or column). Key properties: display:flex, align-items, justify-content, gap, flex-grow. In TheSchoolTech's dashboard: d-flex (Bootstrap utility = display:flex) used for sidebar + content layout. Trainer cards use flexbox for avatar + info alignment.
Q3 What is AJAX? How is it used in TheSchoolTech?
AJAX (Asynchronous JavaScript and XML) — makes HTTP requests from browser without page reload. In TheSchoolTech: Razorpay checkout.js uses AJAX to process payment in popup without leaving the page. The payment handler function is called on success: handler: function(response) { document.getElementById('payment-form').submit(); }.
Q4 What is responsive design?
Responsive design makes websites work on all screen sizes. In TheSchoolTech: Bootstrap 5 grid system (col-md-6 col-lg-4) automatically adjusts columns. d-none d-lg-block hides sidebar on mobile. Media queries in custom CSS: @media (max-width: 991px) { .dash-sidebar { display: none; } }. Mobile gets a simplified nav bar with icon buttons.
Q5 Explain the JavaScript video toggle in TheSchoolTech.
function toggleVideo(id) { const video = document.getElementById('vid_' + id); if (video.paused) { // Pause all others first document.querySelectorAll('video').forEach(v => v.pause()); video.play(); } else { video.pause(); } }
Uses DOM manipulation to find video by ID, controls playback. Event-driven — triggered by clicking the overlay div. Only one video plays at a time — all others are paused first.
Q6 What is the difference between let, var, const?
var — Function scoped, hoisted, can be redeclared. Old style, avoid.
let — Block scoped, not hoisted, can't be redeclared. Use for changeable values.
const — Block scoped, must be initialized, can't be reassigned. Use for fixed values.
In TheSchoolTech's JS: const video = document.getElementById(...), const reader = new FileReader().
PART 11 Scenario-Based Questions
S1 What if two schools try to book the same trainer simultaneously? 🔥
Trainers can have multiple bookings (not exclusive). So two schools can book the same trainer — the trainer manually accepts/rejects. Trainer can decline if already busy. For exclusive slots, add a calendar availability system. For true race conditions, use DB transactions with SELECT FOR UPDATE to lock the trainer record during booking creation.
S2 Razorpay payment succeeds but database update fails — what happens? 🔥
Critical problem! Solution: 1) Wrap DB update in try-catch. 2) If DB fails, log the payment_id. 3) Use Razorpay Webhooks as backup — Razorpay independently notifies our server. 4) Add a reconciliation job that checks Razorpay payment status against our DB. The stored payment_id in booking allows manual fix: check Razorpay dashboard and manually update booking status.
S3 What if an unauthorized user tries to access admin URL directly?
They get a 403 Forbidden. The RoleMiddleware runs first: checks Auth::user()->role. If role is 'school' trying to access /admin/dashboard, the middleware returns abort(403, 'Access Denied'). Laravel's exception handler renders the 403 error page. They never reach the controller.
S4 What if a user submits an invalid booking form?
Laravel's $request->validate() in BookingController@store runs first. If validation fails, Laravel automatically redirects back with errors stored in session flash. Blade displays errors: @if($errors->any()) @foreach($errors->all() as $e). Old input is preserved via old('field') so user doesn't lose their data.
S5 What if someone changes the booking ID in the URL?
In BookingController@show: $school = Auth::user()->schoolProfile; if ($booking->school_id !== $school->id) abort(403); — We verify the booking belongs to the logged-in school. Similarly in trainer routes. Route model binding already ensures the booking exists (404 if not). Authorization check ensures ownership. This prevents IDOR (Insecure Direct Object Reference) attacks.
S6 What if 10,000 users hit the website at once?
Current shared hosting would struggle. Solutions: 1) Add Redis caching for trainer listing (most visited page) — cache for 5-10 minutes. 2) Use Queue for email sending — don't send synchronously. 3) Move to VPS/cloud with more resources. 4) Add CDN (Cloudflare) for static assets. 5) Add database indexes on frequently queried columns. 6) Use lazy loading for images/videos on home page.
S7 What if an uploaded video file is malicious?
1) MIME type validation: 'demo_video' => 'mimes:mp4,mov,avi,webm' — Laravel checks actual file content, not just extension. 2) Files stored outside web root in storage/ — not directly executable. 3) Files accessed via symlink URL, not executed. 4) Could add virus scanning with ClamAV for extra security. 5) Max file size limit prevents large malicious files.
PART 12 Tricky Follow-Up Questions
⚠️ These are the questions that trip up candidates. Know these cold.
T1 "Why did you use Laravel?" → "Why not Core PHP?" 🔥
"Core PHP would require writing everything from scratch — authentication, database connections, CSRF protection, routing, email handling, file storage. Laravel provides all of these out of the box. For a project with booking system, payment integration, role-based auth, and emails, Core PHP would have taken 3x longer. Laravel's conventions also make the code more maintainable."

Follow-up: "But Laravel is heavy?" → "Modern Laravel is very optimized. Route caching, config caching reduce overhead. The productivity gain far outweighs the minimal performance cost for this type of application."
T2 "You used MySQL" → "Why not PostgreSQL or MongoDB?" ⭐
"MySQL is most compatible with shared hosting (Hostinger provides it by default), has excellent Laravel/Eloquent support, and our data is relational — schools, trainers, bookings all have clear relationships with foreign keys. PostgreSQL would also work but adds unnecessary complexity for deployment. MongoDB wouldn't be ideal here because our data is structured with strict relationships, not document-like."
T3 "You store teaching_subjects as JSON" → "Isn't that bad practice?" ⭐
"You're right that it violates strict normalization (1NF). The proper approach is a many-to-many pivot table (trainer_subjects). I chose JSON for faster development. The tradeoffs: can't efficiently JOIN on subjects, can't enforce FK constraints. For the current scale, it works fine. Given more time, I'd create a proper pivot table for better queryability and data integrity."
T4 "How does Auth::attempt() work internally?" 🔥
"Auth::attempt() first fetches the user by email from the database. Then it uses Hash::check() which calls PHP's password_verify() to compare the submitted password against the bcrypt hash stored in DB. Bcrypt includes a random salt in the hash, so even identical passwords have different hashes. If check passes, Laravel creates a session and stores the user's ID. The session cookie is sent to browser for subsequent requests."
T5 "What happens if Razorpay is down during payment?" ⭐
"The order creation in showPayment() would fail and throw an exception. It's wrapped in a try-catch — catch block would redirect back with an error: 'Payment service is temporarily unavailable, please try again.' The booking remains in accepted status. User can retry. For production, I'd add retry logic and monitoring alerts."
